# Context Pilot

[Сайт и установка](https://yevgenevic.github.io/context-pilot/)

Context Pilot помогает продолжить работу в новой сессии ИИ. В локальном дашборде видно, что сделал предыдущий агент, какие файлы изменились и какие проверки прошли.

## Установка

Понадобятся Git и Node.js 22.18 или новее с npm.

```sh
npm install -g https://github.com/yevgenevic/context-pilot/releases/download/v0.2.1/context-pilot-0.2.1.tgz
```

В папке своего Git-проекта выполните

```sh
pilot init
pilot dashboard
```

Откройте адрес из терминала. Команда `pilot doctor` покажет, какие CLI доступны и выполнен ли вход. Для автоматического запуска задач нужен авторизованный Codex CLI. Для продолжения работы вручную в Claude Code скачайте задание во вкладке «Передача».

[Выпуски Context Pilot](https://github.com/yevgenevic/context-pilot/releases)

## Запуск из исходников

Из корня клона установите зависимости дашборда, соберите его и запустите тесты.

```sh
npm --prefix ui ci
npm --prefix ui run build
npm test
```

Команда `npm link` в корне клона добавляет локальную версию `pilot` в терминал. Затем в своём Git-проекте выполните `pilot init` и `pilot dashboard`.

Исходники CLI находятся в [src/](src/), интерфейса — в [ui/](ui/), тесты — в [test/](test/). Чтобы собрать установочный пакет, выполните `npm run release:tgz`. Готовый файл появится в `site/download/`.

## Полный процесс запуска

Новые идеи проходят восемь стадий: подготовку, требования, брифинг, спецификацию, план, разработку, код-ревью и приёмку. Состояние каждого этапа и результаты G1–G4 сохраняются в проекте и видны в дашборде. Пользовательские ответы сохраняются до запуска исполнителей. Независимый читатель сверяет спецификацию с исходной идеей. Каждое требование должно попасть в задачу.

До работы агентов Pilot сохраняет исходный снимок файлов. Финальный агент получает исходную идею с ответами, отдельную исходную копию и новую итоговую копию, чтобы самостоятельно проверить прежнее поведение и новые требования. Копия включает незакоммиченные изменения, исключает историю Git, .pilot, инструкции авторов, .env и node_modules. Для npm-проекта зависимости восстанавливаются по package-lock.json без lifecycle-скриптов. Код-ревью также выполняется в новой копии. Тестам разрешены временные файлы; изменение исходников в копии блокирует завершение. Символические ссылки и файлы больше 16 МиБ требуют отдельной подготовки проекта. Недоступная проверка блокирует завершение. Файлы исходника и копии повторно сверяются, временная копия удаляется после приёмки. На дашборде остаются её SHA-256, число файлов и отчёт.

После остановки используйте кнопку продолжения или `pilot resume ID`. Повторная слепая приёмка всегда начинает с новой копии и исходного брифа. Старые записи продолжают работать по прежнему маршруту. Для нового короткого маршрута из планирования, исполнения и проверки можно задать `PILOT_WORKFLOW=classic`.
